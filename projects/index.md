# Projects

## Purpose

Kanonischer Einstieg in bewusst verfolgte Veränderungsvorhaben.

## Ownership and Boundaries

Jedes Project besitzt genau einen Namespace `projects/<slug>/` und einen gleichnamigen Hauptrecord. Actions, Decisions, Interactions, Domain Truth, Repositories, Assets und Finance bleiben bei ihren eigenen Ownern.

## Navigation

Projects werden über ihren Hauptrecord gefunden; abgeschlossene Zustände bleiben am Project dokumentiert.

## Maintenance

Ein Gedanke ist noch kein Project. Ein Project entsteht erst bei einem bewusst verfolgten Ergebnis, das größer als eine einzelne Action ist.
